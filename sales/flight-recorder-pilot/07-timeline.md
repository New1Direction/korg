# Pilot timeline

Durations count from kickoff and match [README.md](README.md#pilot-at-a-glance):
Recorder 2 weeks, Recorder + CI Gate 3 weeks, Evidence Pack 4 weeks. Pre-kickoff
work (week 0) is not counted.

## Week 0 — before kickoff (customer-paced, usually 1–2 weeks)

| Step | Owner | Exit condition |
|---|---|---|
| Scoping call (30 min) | Both | Tier chosen; ICP checklist passes ([02](02-ideal-customer-profile.md#qualification-checklist-first-call)) |
| Discovery questionnaire returned | Customer | [05](05-discovery-questionnaire.md) answered |
| Fit confirmation | Vendor | Written go/no-go within 2 business days |
| Security review of [06](06-security-and-data-handling.md); NDA and SOW signed | Customer | Signed; first 50% invoice issued |
| Approvals: workstation install, hook registration, CI action (CI tiers) | Customer | Approvals in writing |
| Pilot developers and calendar confirmed | Customer | Names and kickoff date |

## Recorder — 2 weeks

| Day | Activity | Output |
|---|---|---|
| 1 | Kickoff (60 min): goals, acceptance criteria walkthrough, data-sharing level | Agreed plan |
| 1–2 | Install on pilot workstations at a pinned commit; verifiers set up; issuer key generated by the customer | D1, D2, D3, D5 |
| 2–3 | Redaction canary drill with synthetic secrets | First half of D7 |
| 3–8 | Developers work normally on pilot repositories; daily ledger verification spot checks | Ledgers accumulate |
| 5 | Mid-pilot check-in (30 min): early coverage and overhead numbers | Issues list |
| 6–8 | Coverage and overhead measurement; optional backfill | D4, D8 |
| 8–9 | Certificates minted for customer-chosen sessions; tamper and wrong-key drills | D6, rest of D7 |
| 9 | Acceptance run ([09](09-acceptance-criteria.md)) | Criteria results |
| 10 | Report delivered; readout (60 min) | D9 |

## Recorder + CI Gate — 3 weeks

Days 1–9 follow the Recorder plan (install, canary drill, capture, measurement,
Certificates, and tamper drills). Its acceptance run and report move to the end.
Then:

| Day | Activity | Output |
|---|---|---|
| 10–11 | Add the CI gate (`verify-korgcert` action pinned to the issuer key, plus a redaction-lint step, PR comments off unless chosen) to the pilot repositories; one passing PR and one deliberately failing PR, using day-8–9 Certificates | D10 |
| 10–12 | Anchoring demonstration (if opted in) or structural-only memo | D11 |
| 11–12 | Codex CLI feasibility replay of one customer-sanitized trace | D12 |
| 13 | Acceptance run | Criteria results |
| 14–15 | Report and readout | D9 |

## Evidence Pack — 4 weeks

Days 1–12 follow the Recorder + CI Gate plan. Its acceptance run and report move
to week 4, so acceptance runs once, at the end:

| Day | Activity | Output |
|---|---|---|
| 13–15 | Extra capture and measurement time for the larger pilot group; findings consolidated | D4, D8 updated |
| 16 | Control-evidence mapping workshop (half day) with the GRC owner | Draft D13 |
| 16–18 | Operating runbook drafted and reviewed with platform and security owners | D14 |
| 18 | Acceptance run | Criteria results |
| 19 | Report and team readout | D9 |
| 20 | Executive readout | D15 |

## After acceptance

| When | What |
|---|---|
| On acceptance | Final 50% invoiced, payable net 15 ([08](08-pricing.md#payment-terms)) |
| Through support window (14 or 30 days) | Async support by email for the installed configuration |
| Acceptance + 30 days | Vendor deletes any customer artifacts it holds and confirms in writing ([06 §7](06-security-and-data-handling.md#7-retention-and-deletion)) |

## Schedule risks we watch

- **Too few real sessions.** Coverage numbers need real work. If pilot developers
  are behind the three-session minimum at the mid-pilot check-in, we agree a
  catch-up plan. The options are: the customer accepts a smaller sample in writing;
  we extend once by up to 5 business days at no cost; or the customer buys an
  additional pilot week ([08](08-pricing.md#change-orders)).
- **Approvals arriving after kickoff.** These pause the clock
  ([03](03-scope-and-exclusions.md#customer-responsibilities)).
- **Claude Code updates mid-pilot.** A new Claude Code release can change the
  transcript format. We record the version in every measurement and re-run
  coverage checks if it changes.
